GAJA

자전거 여행 위치 기반 HUD 서비스

개인 프로젝트 Spring Boot 위치 기반

프로젝트 개요

GAJA는 자전거 여행 중 경로, 날씨, 주행 상태를 한 화면에서 확인할 수 있는 위치 기반 HUD 서비스입니다. 모바일 환경에서도 사용 가능하도록 설계되었으며, GPS 기반 위치 추적과 기상 데이터 연동을 통해 실시간 주행 정보를 제공합니다.

백엔드에서는 사용자 인증 세션 관리, 위치 데이터 수집 및 가공, 외부 기상 API 연동, 주행 기록 저장과 조회를 담당했습니다.

주요 기능 및 설계

위치 기반 HUD 데이터 파이프라인

클라이언트에서 주기적으로 전송하는 GPS 좌표를 수집하여 주행 경로를 구성합니다. 단순 좌표 나열이 아닌, 이동 거리와 평균 속도를 실시간으로 산출하여 HUD 화면에 노출할 데이터를 가공했습니다.

  • GPS 좌표 수집 간격과 배터리 소모 간의 트레이드오프를 고려하여 적응형 수집 주기를 설계
  • 비정상적인 좌표 편차(예: 터널, 고층 건물)를 필터링하는 로직 구현
  • 주행 종료 시 경로 데이터를 압축 저장하여 저장소 효율 확보

인증 및 세션 관리

야외 활동 특성상 네트워크 불안정 환경이 예상되어, 세션 유실 시에도 사용자 경험을 유지할 수 있도록 설계했습니다.

  • JWT 기반 상태less 인증을 채택하여 서버 세션 의존성 제거
  • Access Token / Refresh Token 분리로 보안과 편의성 균형 확보
  • 비정상 종료 시에도 주행 데이터가 유실되지 않도록 로컬 캐시 동기화 로직 설계

외부 API 연동 및 장애 대응

기상 정보는 외부 기상청 API를 통해 실시간으로 조회합니다. 외부 서비스 의존성으로 인한 장애 전파를 방지하기 위해 다음과 같은 대응을 구현했습니다.

  • API 응답 실패 시 Fallback 캐시 데이터 제공
  • Rate Limiting을 고려한 요청 큐 및 재시도 로직 구현
  • Timeout 기준을 명시하여 장기 지연 시 빠른 실패(Fail-fast) 유도

기술적 고민

실시간성과 배터리 소모의 균형

GPS는 배터리 소모가 큰 센서입니다. 주행 중 지속적인 위치 추적이 필요하지만, 과도한 수집 주기는 디바이스 부하를 가중시킵니다. 이에 따라 주행 상태(정지/저속/고속)에 따라 수집 주기를 동적으로 조정하는 로직을 추가했습니다.

정지 상태: 30초 간격 / 저속(15km/h 이하): 10초 간격 / 고속: 5초 간격. 상태 전이 시 이벤트 기반으로 주기를 변경하여 불필요한 GPS 호출을 줄였습니다.

데이터 정합성

주행 기록은 시간 순서가 중요한 데이터입니다. 네트워크 지연이나 비정상 종료로 인해 좌표 순서가 뒤섞이거나 누락될 수 있으므로, 서버 수신 시 타임스탬프 기준 정렬과 중복 제거를 수행하여 데이터 정합성을 보장했습니다.

비운영 환경 부하 테스트

실제 서비스 트래픽이 아닌 비운영 테스트 환경에서 k6로 조회 경로의 응답 특성을 확인했습니다. 20 → 50 → 100 concurrent backend read 시나리오를 실행했고, 100명 조건에서 overall p95 12.41ms를 기록했습니다.

이 수치는 실제 운영 사용자 지표가 아니라, 테스트 환경에서 조회 경로가 어떤 응답 특성을 보이는지 확인하기 위한 synthetic load benchmark입니다.

회고

GAJA 프로젝트를 통해 실시간 데이터 수집 파이프라인과 외부 API 연동의 장애 대응 패턴을 직접 설계할 수 있었습니다. 특히 네트워크 불안정 환경을 가정한 설계가 사용자 경험에 미치는 영향을 체감했으며, 이후 프로젝트에서도 상태 분리와 로컬 캐시 전략을 적극적으로 활용하게 되었습니다.
