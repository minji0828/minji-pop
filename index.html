Flow-first Backend

복잡한 도메인에서도 먼저 흐름을 파악하고, 제어 가능한 구조로 정리하는 백엔드 개발자.

기능을 바로 붙이기보다 사용자 흐름, 상태 변화, 데이터 경계를 먼저 정리한 뒤 필요한 지점을 깊게 파고드는 편입니다. 이 포트폴리오는 GAJA, Shortudy, AI-STUDY에서 어떤 흐름을 먼저 읽었고, 어떤 기준으로 시스템을 원하는 방향에 가깝게 유도했는지를 보여주기 위해 정리했습니다.

How I Approach Problems

구현을 시작하기 전에 먼저 전체 흐름을 보고, 그 안에서 어떤 상태가 흔들리고 어떤 규칙이 충돌하는지부터 정리합니다. 이후에는 필요한 지점을 깊게 파고들어 문서, 테스트, 구조로 다시 고정하는 방식으로 일합니다.

How I Think

기능 구현보다 먼저 흐름과 상태를 읽고, 변수 많은 시스템을 원하는 방향으로 유도할 수 있는 기준을 세우는 편입니다.

  • 전체 흐름을 먼저 보고 어디서 상태가 흔들리는지 찾습니다.
  • 도메인 규칙과 데이터 경계를 먼저 정리한 뒤 구현으로 내려갑니다.
  • 실시간으로 변하는 입력은 완전히 통제하기보다 원하는 방향으로 유도하는 구조를 선호합니다.
  • 문제가 생기면 원인과 흐름을 끝까지 파고들며 학습하는 편입니다.
  • 도메인이 달라도 먼저 공통 흐름을 읽고 규칙을 잡는 데 강점이 있습니다.
  • 문서와 테스트로 구현 계약을 다시 고정해 재현 가능한 구조를 만들려고 합니다.
