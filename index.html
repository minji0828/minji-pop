Introduction

문제 정의와 기준 설계에 강한 백엔드 개발자.

위치 기반 조회 로직, 인증/보안 흐름, 운영 관측성처럼 서버가 책임져야 하는 기준을 프로젝트로 검증해 왔습니다. 이 포트폴리오는 GAJA, Shortudy, AI-STUDY에서 어떤 문제를 정의했고 어떤 구조로 풀었는지를 보여주기 위해 정리했습니다.

Core Focus

기능을 많이 붙이는 것보다, 현재 문제에 맞는 기준과 데이터 흐름을 먼저 정리하는 편입니다. 구현한 기능이 왜 그 구조여야 했는지 문서와 사례로 설명하는 데 집중했습니다.

How I Work

프로젝트에서는 기능 추가보다 문제 정의, 조회 경로, 인증 흐름, 운영 기준을 먼저 정리하는 편입니다.

  • 요구사항과 상태 기준을 먼저 문서와 ADR로 정리합니다.
  • 조회 경로와 데이터 흐름을 나눠 병목 지점을 확인합니다.
  • 인증과 상태 전이처럼 기준이 필요한 영역을 먼저 고정합니다.
  • 문서와 테스트로 구현 계약을 맞추는 편입니다.
  • 도입 기술보다 현재 조건의 트레이드오프를 우선합니다.
  • 구현 후에도 운영 시나리오와 예외 흐름을 다시 점검합니다.
